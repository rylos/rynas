# Translating rynas

English is the source language: every text has a stable key and its English text in the code.
Every other language is a set of plain text files, one per part of the interface. This page is
for translators and for whoever adds a text.

## Files

```
crates/rynas-ui/assets/i18n/
  languages.txt            the language table
  it/                      one folder per language, named after its code
    core.txt               the web interface
    module-synology.txt    the Synology module's screens and events
    module-qnap.txt        the QNAP module's screens and events
    files.txt              the File app
    notify.txt             notification messages (e-mail, ntfy, webhooks…)
```

Where the English of each part lives:

| Part | English source |
|---|---|
| `core` | `crates/rynas-ui/src/i18n.rs` (`dict!` table) |
| `module-<name>` | `crates/rynas-ui/src/modules/<name>/i18n.rs` |
| `files` | `crates/rynas-ui/files-app/js/lang/en.js` |
| `notify` | `crates/rynas-notify/src/engine/template.rs` (`EN`) |

Notification channels also use the `nev.*` (event texts) and `task.*` (task names) lines of
`core.txt` and of the module files, so the web interface and the messages say the same thing.

## The language table

`languages.txt` has one line per language, fields separated by a TAB:

```
code    native name    default locale    plural categories    English name
it      Italiano       it-IT             one other            Italian
```

- **code**: a BCP 47 tag (`it`, `pt-BR`); also the folder name and the value stored in
  preferences and notification targets.
- **native name**: how the language names itself; menus show it like that in every language.
- **default locale**: dates and numbers when the browser names no region of the language. When it
  does (`it-CH`), that region wins.
- **plural categories**: the [CLDR plural categories](https://cldr.unicode.org/index/cldr-spec/plural-rules)
  of whole numbers in the language (`zero one two few many other`), the forms each counted text
  needs. `other` is always required. English and Italian use `one other`; Polish `one few many other`;
  Japanese `other`.
- **English name**: the command palette also finds the language by it.

English is the first line and has no folder.

## Adding a language

1. Add its line to `languages.txt`.
2. Create `assets/i18n/<code>/` with the five parts, copying the Italian files as a starting
   point, and translate every text.
3. Run `cargo test -p rynas-ui -p rynas-notify`. The completeness tests list, per language and
   part, missing keys, stale keys (no longer in the source), placeholders that differ, plural
   forms the language needs and empty texts.

Nothing else changes: the language menus, browser detection, the loaders of the interface and
of the File app, and the notification channels all read the table. The build joins `core.txt`
and the module files into one download per language (`i18n-bundle.sh`).

## File format

One entry per line, the key, a TAB, the text:

```
# comments start with #
nav.storage	Archiviazione
fmt.of	{part} di {total}
```

- UTF-8, no TAB or newline inside a text. Leading and trailing spaces count.
- The order of the lines does not matter; the files follow the source order so diffs stay small.
- A key missing from a file shows its English text, never an empty one.

## Placeholders

`{name}` is replaced by a value: `{part} di {total}`. Keep every placeholder of the English
text, with the same name; move it wherever the sentence needs it. Do not translate the name.

## Plural forms

A counted text has one key per plural category, `key.<category>`:

```
rm.count.one	{n} disco
rm.count.other	{n} dischi
```

The interface picks the category with `Intl.PluralRules` for the number and the locale, then
falls back to `key.other`. Give every category of your language's line in the table; `{n}` is
the formatted number and may be left out where the word says it ("un disco").

## Words and style

The glossary (one term per concept, in English and Italian) and the style rules (sentence case,
quotes, button and title wording) are in [quality/guidelines.md](quality/guidelines.md), section
"Glossary and text style (G8f)". Use the same term for the same thing in every part.

## For developers

- A new text: a key and its English in the part's source, then its line in every
  `assets/i18n/<code>/<part>.txt`. Use `t`/`tr`/`tf`, `tn` for counts (core) and `t`, `count`
  (File app); never build sentences by concatenation.
- Numbers, sizes, dates and durations come from the formatters (`i18n::num`, `bytes`, `datetime`,
  `duration`… and the File app's `format.js`): separators from `Intl`, unit words from the
  `dur.*`/`fmt.*` texts. No code may test for a language.
- Tests: `i18n_check::translations_are_complete` (core and modules), `files_check::files_*` (File
  app), `template::tests::notify_translations_are_complete` (notifications). The test build also
  loads a made-up third language (`crates/rynas-ui/tests/fixtures/i18n`, Polish with four plural
  forms) to prove a new language works without shipping it.
