| D-MODULE | Hardware module boundary | Synology code spread in the core behind `if synodeb` · hardware modules behind core extension points | **"tutte le cose synology vivono solo nel 'modulo' synology. altri moduli arriveranno per altri hardware in futuro. se non lo si ha deve funzionare tutto e senza rimandi a cose che non sono standard."** The core works on any Debian with standard tools only (NUT in `/etc/nut`, udev `UDISKS_IGNORE`/`UDISKS_SYSTEM`, its own notification engine) and names no platform in code paths or UI texts. A hardware module is detected at the start of rynasd (Synology: its hardware via DMI/platform driver, or synodeb's own files) and fills in extension points of `rynas-module`: `UpsLayer` (a layer that runs NUT itself: probe/setup/status/tests/policy file/pre-shutdown notice), `EventForward` (the local notify socket opens only then), `notify_import`, `system_disk_usb_ids`, `domains`, `start` (hooks into its layer; the package ships them under `/usr/lib/rynas/modules/<module>/`, never into the layer's `/etc`; adopts the layer's settings into its keys), `router` (its HTTP routes, nested by rynasd under `/v1/modules/<id>` and forwarded by rynas-web by prefix: `/api/v1/modules/<id>/…`), `hardware_control` (provider-neutral bay identify `/api/v1/hardware/bays/{n}/identify`), `boot` (`BootLayer`: a boot device of its own on the kernel card and the boot half of a root rollback; none: `/boot` only, rollback refused `no_boot_layer`), `rescue_feedback` (beeps/LEDs of the network rescue paths), `reset_button` (read-only on Network › Rescue), `wake_clock` (the RTC of the power schedule and the unit that reads its alarm). rynas-web picks a module's hardware provider (`rynas_web::hardware::detect`), whose `thermal_limits` feed the hardware watch. The UI has `src/modules/<module>/` (pages, tabs, its own dictionary table read by the single i18n mechanism) and reaches the core only through slots (`modules::ups_key`, `source_label`); a module's texts are shown only where it answers. Pragmatic exceptions: wire types stay in `rynas-api-types` (module namespaced; the core's are generic), one detection line per module in `rynasd::modules::detect` (rynasd, rynasctl) and `rynas_web::hardware::detect`. | D-TIME | Date, time and time zone | rynas config key applied to the system · the system as the state (timedated + the daemon's drop-in) · always install chrony | **the system is the state** (no configuration key): time zone, hardware clock and manual time through timedated (`timedatectl`), so rynasd's sandbox keeps `ProtectClock=yes`; the time daemon is **detected, both supported**: chrony when installed, else `systemd-timesyncd` (Debian's default), with none sync on installs `systemd-timesyncd`; sync on/off = `timedatectl set-ntp` (timesyncd) or `systemctl enable/disable --now chrony.service`; up to 8 own servers in one drop-in (`timesyncd.conf.d/60-rynas.conf` with a resetting `NTP=`, or `/etc/chrony/sources.d/rynas.sources` + `chronyc reload sources`), empty = the distribution's servers, chrony's own `chrony.conf` sources stay (no conffile edits); manual time only with sync off (`set-time @epoch` for "use this browser's time", or a wall time in the system zone); a local-time RTC is warned with a move to UTC, never the reverse; after a zone change rynasd re-reads it (`tzset`) and `rynas_power::system_tz` reads `/etc/localtime` each time (jiff caches five minutes); notifications `system.clock_unsynced` (sync on, not synchronized for 1 h) and `system.clock_drift` (> 1 s in two looks). | D-PROCESSES | Process manager (System › Processes) | none (shell, htop) · a terminal clone (btop/htop in the browser) · grouped by what the user knows | **grouped view first**: processes under their system service, container (named after the catalogue app), login session, user services, kernel threads (hidden by default), with group totals; flat and tree views sortable by CPU, memory (RSS; PSS in the detail), disk read/write rate and age; filter as you type; a detail panel (command line, user, state, threads, nice, I/O class, cgroup, start time, listening ports, CPU/memory graph kept in the browser for the selected process only, ≤ 150 points).
