| D-MODULE | Hardware module boundary | Synology code spread in the core behind `if synodeb` · hardware modules behind core extension points | **"tutte le cose synology vivono solo nel 'modulo' synology. altri moduli arriveranno per altri hardware in futuro. se non lo si ha deve funzionare tutto e senza rimandi a cose che non sono standard."** The core works on any Debian with standard tools only (NUT in `/etc/nut`, udev `UDISKS_IGNORE`/`UDISKS_SYSTEM`, its own notification engine) and names no platform in code paths or UI texts. A hardware module is detected at the start of rynasd (Synology: its hardware via DMI/platform driver, or synodeb's own files) and fills in extension points of `rynas-module`: `UpsLayer` (a layer that runs NUT itself: probe/setup/status/tests/policy file/pre-shutdown notice), `EventForward` (the local notify socket opens only then), `notify_import`, `system_disk_usb_ids`, `domains`, `start` (hooks into its layer; the package ships them under `/usr/lib/rynas/modules/<module>/`, never into the layer's `/etc`; adopts the layer's settings into its keys), `router` (its HTTP routes, nested by rynasd under `/v1/modules/<id>` and forwarded by rynas-web by prefix: `/api/v1/modules/<id>/…`), `hardware_control` (provider-neutral bay identify `/api/v1/hardware/bays/{n}/identify`), `boot` (`BootLayer`: a boot device of its own on the kernel card and the boot half of a root rollback; none: `/boot` only, rollback refused `no_boot_layer`), `rescue_feedback` (beeps/LEDs of the network rescue paths), `reset_button` (read-only on Network › Rescue), `wake_clock` (the RTC of the power schedule and the unit that reads its alarm). rynas-web picks a module's hardware provider (`rynas_web::hardware::detect`), whose `thermal_limits` feed the hardware watch. The UI has `src/modules/<module>/` (pages, tabs, its own dictionary table read by the single i18n mechanism) and reaches the core only through slots (`modules::ups_key`, `source_label`); a module's texts are shown only where it answers. Pragmatic exceptions: wire types stay in `rynas-api-types` (module namespaced; the core's are generic), one detection line per module in `rynasd::modules::detect` (rynasd, rynasctl) and `rynas_web::hardware::detect`. Audit (every former "move later" item done in the follow-up of the same day): `../quality/module-boundary-2026-11-06.md` | **taken** 2026-11-06 |
