# rynas — User interface (proposal)

Source: `research/03-ui-ux.md` (full mockups, computed WCAG contrast ratios, URLs).

## Layout: three proposals

| | Idea | Pros | Cons |
|---|---|---|---|
| **A** (recommended) | sidebar + widget dashboard + command palette | a URL for every view, mobile, easy plugins | less "wow" than DSM |
| B | DSM-style windowed desktop | familiar to Synology users, multitasking | no URLs, mobile impossible, hard accessibility, heavier bundle |
| C | Proxmox-style resource tree + task log | extremely dense, for experts | intimidates less experienced users, no dashboard |

**Proposal: A + two borrowings from C**: a collapsible task panel at the bottom (Proxmox) and an
optional tree in the Storage section. From DSM we only take the **physical bay view**.

- Self-hosted fonts (OFL): **Inter** (tabular figures) + **JetBrains Mono** for paths, logs, terminal.
- Scale 12/13/**14**/16/20/24/32 px; 4 px grid; radius 4/8/12.
- **Lucide** icons (+ Tabler where missing); for the file manager, SynoFile's **eza** icons/colors.
- States always shown with icon + text + color (● Healthy ▲ Degraded ✕ Failed ◌ Unknown).
- Theme saved on the server per user + local copy; inline script in `<head>` against the white
  flash (lesson from "Pacchetti DSM fatti in casa", the homemade DSM packages note).

## Key patterns
1. Dashboard with reorderable widgets (12-column grid, Edit mode, keyboard accessible too).
2. **Visual Storage Manager**: chassis with bays from the hardware profile (synology plugin →
   real DS923+/DS920+; otherwise generic grid/SES), LEDs, temperature, pool; "Identify" blinks
   the bay LED.
3. Pool/share wizards with capacity calculation and a **command preview**; typed confirmation for destructive actions.
4. **Pending changes** with list of services and diff; "Apply and verify" with rollback (network).
5. Notifications (toasts + bell) and a **task panel** with streaming logs.
6. **Command palette Ctrl+K** (navigation, actions, entities, plugin commands).
7. Share permissions as a **matrix** users × shares with effective permission.
8. Live log viewer (journald) with filters in the URL; web terminal (xterm.js) with re-authentication.
9. Responsive: drawer < 1024 px, bottom bar < 768 px, tables → cards.

## File manager (SynoFile model)
Top-level **Files** section, same experience as SynoFile: tabs, dual pane,
eza list / grid / columns, keyboard first (F3 F4 F5 F6, Ctrl+T, `/`, Vim keys),
transfer dialog with graph, archives as folders, ring-chart space analysis,
quick look (HEIC in WASM), micro-style editor, SMB/SFTP connections, `#recycle` bin.
Every operation runs as the logged-in user (see `03-modules-roadmap.md`).

## Plugins in the UI (contribution points)
The plugin **declares** in its manifest what it adds; the shell decides look and placement.

```toml
[ui]
nav      = { section = "Plugins", label = "Docker", icon = "container", route = "/p/docker" }
widgets  = [{ id = "docker.summary", sizes = ["S","M"] }]
pages    = [{ route = "/p/docker/*", type = "table", schema = "containers.schema.json" }]
panels   = [{ target = "storage.volume.tabs", label = "Docker volumes" }]
settings = { schema = "settings.schema.json" }   # generated form, part of pending changes
commands = [{ id = "docker.restart", label = "Restart container…" }]
```

Rules (manifest linter): tokens only (no hard-coded colors), icons from the official set, i18n strings.
Languages: English (primary) and Italian from day one, then SynoFile's 9 languages.
