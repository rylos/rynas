# Backend fixes — 2026-11-05 (after wave B)

Scope: the open backend findings of [`review-2026-11-05-wave-a.md`](review-2026-11-05-wave-a.md)
and [`review-2026-11-05-wave-b.md`](review-2026-11-05-wave-b.md). Rules `A*`, `M*` are in
[`guidelines.md`](guidelines.md). One commit per item, each with tests.

## Done

| Finding | Fix |
|---|---|
| wave B M3 (M1) | **Event stream caps** (`rynas-web/src/streams.rs`). `/events`, `/metrics/stream` and the forwarded `/tasks/stream` take a slot: at most **6 per session** and **128 in total**. Over the session cap the session's **oldest** stream is closed (an `AbortHandle`), never the new one: a page restored from the bfcache or a half-open connection cannot lock the visible page out. 6 is the HTTP/1.1 per-origin limit of a browser, so one browser never evicts a stream it is really reading and two tabs cannot evict each other in a loop. Over the global cap: `429 rate_limited` + `Retry-After: 5` (evicting another user's stream would let one session disturb all others). The slot is dropped with the response stream; the table holds at most 128 entries and a session leaves it with its last stream. |
| wave A M11 | **`GET /config/pending`: `ETag` / `304`**. Strong tag = FNV-1a of the body (covers user, `?detail`, `conflict` flags); `If-None-Match` (also a list or `W/`) → `304` without a body. rynas-web forwards `If-None-Match` and `ETag`. API answers stay `no-store` (A26): the client keeps the tag and the last body. **`config.pending` event on `/events`** (`PendingEvent {generation}`): `rynas-config` bumps a generation on every stage, non-empty discard and apply (an apply also flips other users' `conflict` flags); rynasd adds `config_pending` to `/v1/tasks/stream?config=1`, so `/events` still uses **two** upstream connections. A resync of that stream is sent as `resync {"stream":"tasks"}` **and** `resync {"stream":"config"}`. The UI still polls every 30 s: switching it to the event (and to `If-None-Match`) is a UI task. |
| wave A m17 | **`Location` on every 201**: users, groups, shares, scheduler tasks, snapshot jobs, notification targets/rules/silences, through one `rynasd::error::created()` (id percent-encoded). |
| wave A m19, A10, A13 | **No serde text in errors.** New crate `rynas-http`, used by both daemons, replaces the two copies of the `JsonRejection` mapping and of the `json_errors` middleware. Codes: `invalid_json`, `missing_field`, `unknown_field`, `invalid_type`, `invalid_value` (not in the accepted set or range), with `field` from the deserializer's path (`smb.veto_files`, `members[2]`) and a short English message; serde's text goes to `tracing::debug!`. Query string rejections: `bad_request` + `field` = the parameter, message `invalid query parameter limit`. Other framework rejections: generic message per status. rynasd's hand-parsed bodies (bay identify, diagnostics, rescue) use `rynas_http::from_slice` / `from_value`. |
| wave A m20, A14, A16 | **Closed sets as enums**: `UserStatus.badges: Vec<UserBadge>` (`smb-password-reset` → `smb_password_reset`), `ScrubStatus.status: ScrubState` (`unknown` for a word this version does not know), `Disk.power_state` of `GET /storage` = the shared `PowerState` (same wire words). |
| wave A m15 | **One implementation of the name rules**: `rynas_api_types::validate` (no dependencies, builds for wasm): disk name, host name, account name + reserved names, share name, workgroup, volume label + reserved labels, subvolume name. The duplicate disk-name check of rynasd and rynas-web is gone; rynas-config, rynas-storage and rynas-services re-export the shared functions. |
| planner `field` | **`StoragePlan.issues`**: one `PlanIssue {code: PlanIssueCode, field, subject}` per entry of `errors`, same order. Fields: `label`, `level`, `disks`, `array`, `old`, `new_disk`, `filesystem`. rynasd's 400 for an invalid plan takes `field` from the first issue (was a match on the label message). |
| IoScheduler `adios` | **Not added.** ADIOS (Adaptive Deadline I/O Scheduler) is an out-of-tree scheduler (CachyOS patch set / standalone module): mainline `block/Kconfig.iosched` defines only `MQ_IOSCHED_DEADLINE`, `MQ_IOSCHED_KYBER` and `IOSCHED_BFQ` (checked on `torvalds/linux` master). The development host shows `adios` only because it runs a CachyOS 7.3 kernel (`CONFIG_MQ_IOSCHED_ADIOS=y`); Debian kernels do not have it. Decision 2026-11-05 (Marco): not included, neither in rynas nor in the synodeb kernel; no public benchmarks or releases, lower HDD throughput by the author's own FAQ. Revisit if it is merged upstream. |

UI adaptations the API changes required (kept minimal): `pages/users.rs` (badges), `pages/storage/volume.rs`
and `pages/storage/mod.rs` (scrub state), `pages/dashboard.rs` (standby count), `demo.rs` (demo disks).

## Left open (documented, not done)

- **UI side** of M11 (subscribe to `config.pending`, send `If-None-Match`), of m15 (use
  `rynas_api_types::validate` instead of the hand-written copies; today the UI's workgroup and
  label rules differ from the server's) and the i18n texts above.
- **Plan warnings** stay free text (`StoragePlan.warnings`); only errors have codes.
- **Domain validation messages** (`invalid_value` from `rynas-services`, `rynas-net`, …) have
  a field but no finer code: the UI translates `invalid_value` + field. A per-rule code
  (`invalid_workgroup`, `reserved_name`, …) for every validator is a larger change across the
  domain crates.
- **Task errors** (`TaskInfo.error`) are free text from the task; no code.
- **Remaining string sets** in the API types: `RaidArray.level/state` and `MdArray.level/state`
  (kernel words, partly open: `linear`, `container`, combined md states), `MdMember.state`,
  `SyncProgress.action`, `HardwareStatus.status_led`, `HardwareStatus.events` as tuples (A15),
  `StoragePlan.operation`, `StoragePlan.summary` as tuples.
- wave A m18 (staging deletes 200 vs 204 in the guideline table) and wave B m4 (deprecated
  `/metrics/stream`, `/tasks/stream`): decisions, not code; unchanged.

## Measurements

Release builds from a private target dir, `rynasd --dry-system` (private socket and state dir,
`--storage-check-interval 0`), `rynas-web --users-file` on a localhost port; one session opens 10
`/events` with `curl -N`, 0.2 s apart.

| Process / state | VmRSS | RssAnon | Threads | fds |
|---|---|---|---|---|
| rynasd, idle after 1 min | 15.7 MB | 2.4 MB | 3 | 19 |
| rynas-web, idle after 1 min | 6.4 MB | 1.1 MB | 3 | 10 |
| rynasd, 10 `/events` asked, 6 kept | 15.8 MB | 2.4 MB | 3 | 31 (= 19 + 2 × 6) |
| rynas-web, same | 6.7 MB | 1.4 MB | 3 | 28 (= 10 + 6 TCP + 12 upstream) |
| rynasd, 3 s after the streams closed | 7.8 MB | 2.4 MB | 1 | 19 |
| rynas-web, same | 5.3 MB | 1.4 MB | 3 | 10 |

Both daemons stay under 20 MB. Of the 10 streams the server closed the 4 oldest (their `curl`
exited); file descriptors return to the idle count. rynasd's idle VmRSS is file-backed pages of
the binary (anon 2.4 MB; it drops to 7.8 MB once the kernel reclaims them). `GET /config/pending`
answers 200 with `ETag`, then 304 with `If-None-Match`; `GET /tasks?limit=abc` answers
`{"code":"bad_request","message":"invalid query parameter limit","field":"limit"}`.

Verified: `cargo clippy --workspace --all-targets -- -D warnings`,
`cargo clippy -p rynas-ui --target wasm32-unknown-unknown -- -D warnings`, `cargo test --workspace`.
