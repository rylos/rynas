## Findings

### Critical

**C1 — glibc keeps every large transient buffer resident: RSS 3× the budget after a few logins.**
`crates/rynas-web/src/main.rs:163` sets only `M_ARENA_MAX`; `crates/rynasd/src/main.rs:340` sets nothing.
glibc raises its mmap threshold after the first large free, so the next 19 MiB argon2 block
(`crates/rynas-auth/src/realm.rs:98`, semaphore of 2 at `:128`), a brotli window or a 1 MiB task-log
chunk (`crates/rynasd/src/ops.rs:354`) lands in the heap and is never returned. Measured: 6 MB → 64.7 MB
after five logins, permanently; with a fixed threshold it goes back to 6.5 MB. With `--users-file` any
unauthenticated client can trigger it from the login form; the packaged setup logs in through PAM in
rynasd (no argon2), but the same mechanism applies to every other large transient buffer in both
daemons (dynamic compression, m5: +7 MB; task-log chunks; large JSON answers).
Rule M5, M6. Fix: in both `main()` call `mallopt(M_MMAP_THRESHOLD, 256 << 10)` and
`mallopt(M_TRIM_THRESHOLD, 1 << 20)` next to `M_ARENA_MAX` (or set `GLIBC_TUNABLES` in both units);
reduce the argon2 semaphore to 1. Owners: web, rynasd, auth.

**C2 — release builds show fabricated data when the API does not answer.**
`crates/rynas-ui/Cargo.toml:35` has `default = ["demo"]`; `crates/rynas-ui/src/live.rs:131-145`
switches to the demo data set on any non-401 failure of the first `/auth/session` call (rynas-web
restarting, a proxy 502, a network blip). A NAS UI that can show healthy fake disks during an outage
is a correctness problem, and the feature costs 4.9 KiB brotli. Rule G14. Fix: `default = []`, enable
`demo` only for `trunk serve`/screenshots (`--features demo` or `?demo` in debug builds), and keep the
offline state with retry in release. Owner: UI.

**C3 — a hung network mount can take the whole web server down.**
`crates/rynas-web/src/main.rs:217` limits the blocking pool to 4 threads; `crates/rynas-web/src/api.rs:188`
runs `statvfs` of NFS/CIFS mounts on that pool and only abandons the *future* after 2 s — the
thread stays stuck in the kernel. Four `/storage` calls (the UI polls it every 30 s per tab) exhaust
the pool, and from then on `ServeDir` (tokio::fs), `index.html`, `/system`, `/hardware` and every other
`spawn_blocking` hang too. Rules S7, A25. Fix: probe network mounts on a dedicated thread (or a
`stat` child process killed on timeout) with at most one probe in flight per mount and the last result
cached; mark the filesystem `stale` instead of blocking. Owner: web.

### Major

**M1 — three different ways to call rynasd from rynas-web.** Auth/TOTP: typed `RynasdClient::call`
(`crates/rynas-web/src/rynasd_client.rs:99-150`); config/tasks: raw proxy `forward`
(`crates/rynas-web/src/proxy.rs:47-125`); storage: `StorageBackend` trait returning
`serde_json::Value` (`crates/rynas-web/src/storage_api.rs:33-84`, decoded to `Value`, then to the type,
then serialized again). Consequences: different error codes for the same outage (M2), different
timeouts, storage reads without `x-rynas-user` (no audit, rule A6), unbounded `collect()` of the
upstream body (`rynasd_client.rs:131-136`), three code paths to test. Rule A6, M3. Fix: one
`RynasdClient::forward` used by every protected route (pass-through for plain reads, typed decode only
where rynas-web must enrich, e.g. bays in `add_hw`), always with the user header and a capped body.
Owner: web.

**M2 — the error registry is not the source of truth.** Codes used but not in
`rynas_api_types::error_codes`: `storage_unavailable` (`crates/rynas-web/src/storage_api.rs:57`, and
`docs/phase1/plan.md`), `bad_gateway` (`storage_api.rs:70`), `provider_error` (`crates/rynas-web/src/api.rs:152`),
`internal` (`api.rs:38`, `crates/rynasd/src/server.rs:109,279,294`, `crates/rynasd/src/ops.rs:73,87,132,359`),
plus literals `"bad_request"`/`"not_found"` instead of the constants (`server.rs:89,106,126,156,219,276,320`,
`auth.rs:95,124,227`, `storage_api.rs:125,155`, `api.rs:115`). Same outage, two codes:
`backend_unavailable` (config/tasks) vs `storage_unavailable` (storage). 413 is sent with code
`bad_request` (`proxy.rs:62-63`). Rules A9, A11, A12. Fix: add `INTERNAL`, `BAD_GATEWAY`,
`TIMEOUT`, `PAYLOAD_TOO_LARGE`, `METHOD_NOT_ALLOWED` to the registry, drop `storage_unavailable` and
`provider_error` for `backend_unavailable`, replace every literal with the constant, add a test that
greps the crates for code literals. Owners: types, web, rynasd.

**M3 — query-string, 405 and other rejections are plain text.** Measured:
`GET /api/v1/tasks?limit=abc` → `400 text/plain "Failed to deserialize query string…"`
(`crates/rynasd/src/ops.rs:209-219,330-332,341-357` use bare `Query<…>`); `DELETE /api/v1/system/hostname`
→ `405` with empty body. The UI's `ApiErr` then has an empty code. Rule A8. Fix: a `Query` wrapper
mapping the rejection to `ApiError{bad_request}` (like the existing `JsonRejection` conversion), and a
`method_not_allowed_fallback` returning `ApiError` on both routers. Owners: rynasd, web.

**M4 — duplicate command runners: `rynas_storage::host::SystemHost::run` vs `rynas_tasks::cmd::Cmd`.**
`crates/rynas-storage/src/host.rs:68-120` reads stdout/stderr with `read_to_string` (no cap), kills
only the child (not its process group), polls `try_wait` every 10 ms, and spawns two OS threads per
command; `crates/rynas-tasks/src/cmd.rs` already has a 1 MiB capture cap, process groups,
SIGTERM→SIGKILL and cancellation, and `rynas-config` uses it. Rules M3, "one runner". Fix: make
`SystemHost::run` a thin adapter over `Cmd` (blocking variant, or `Handle::block_on` on the rynasd
runtime handle), keep the `Host` trait for fixtures. Owners: storage, config/tasks.

**M5 — duplicate storage models and parsers.** `GET /api/v1/storage` (rynas-web,
`crates/rynas-web/src/storage.rs`, own `parse_mdstat` at `:145`, `/sys/block` walk at `:83`) returns
`Disk`/`RaidArray` with `power_state: String`, `level: String`, `state: String`
(`crates/rynas-api-types/src/lib.rs:94-123`), while `/api/v1/storage/disks|arrays` (rynasd,
`crates/rynas-storage/src/md.rs:118` another `parse_mdstat`) return `DiskSummary`/`MdArray` with
enums `PowerState`, `RaidLevel`, `ArrayHealth`. The UI maps both to pills differently. Rule A16. Fix:
keep the cheap unprivileged overview only for the dashboard, but build it from `rynas-storage`'s pure
parsers (move `lsblk`/`mdstat`/sysfs parsing into a no-root module the web can call) and reuse the
shared enums; deprecate `Disk`/`RaidArray` for `DiskSummary`/`MdArray` subsets. Owners: types, web, storage.

**M6 — unit and naming drift in API types.** `rx_bps`/`tx_bps`/`read_bps`/`write_bps` are bytes/s
but read as bits (`lib.rs:59,70`); temperature is `celsius` in metrics (`lib.rs:82,170`) and
`temperature_c` in storage; percentages are `*_pct`, `pct` and `percentage_used` (`storage.rs:198`);
throughput `speed_kib_s` (`storage.rs:286`) vs bytes elsewhere; `read_ms` is a timestamp
(`storage.rs:142,439`) but reads like a duration; hardware events are
`Vec<(String, String)>` with local-time strings (`lib.rs:151`); enums use `rename_all = "lowercase"`
(`lib.rs:240,304,396,451,491`, most of `storage.rs`) while `CheckStatus`/`PlanAction` use `snake_case`.
Rules A14, A15. Fix: before v1 is frozen, rename to `rx_bytes_s`, `temperature_c`, `*_pct`,
`*_bytes_s`, `read_at_ms`; events → `struct HwEvent { ts_ms, text }`; all enums `snake_case`
(no wire change for single-word variants). Owners: types (+ every producer/consumer).

**M7 — storage requests are serialized behind one lock with no single-flight or cache for the cheap
reads.** `crates/rynasd/src/server.rs:286-297` (`with_storage`) holds a `tokio::Mutex` for the whole
blocking call; every `/storage/tree` or plan re-runs lsblk/mdadm/btrfs (43 ms here, ~150 ms on the
J4125), and a first SMART view can hold the lock for up to 90 s (`rynasd_client.rs:30`), during
which every storage call queues — including requests whose client already gave up. Rules S8, A25.
Fix: cache the inventory snapshot for ~5 s with single-flight; plans compute on the cached snapshot;
SMART reads per disk outside the global lock; drop waiters whose client disconnected (check before
taking the lock, `tokio::select!` with a deadline). Owners: rynasd, storage.

**M8 — timeouts and their mapping are inconsistent.** rynas-web → rynasd: 15 s auth, 30 s
forwarded (headers only), 90 s storage (`rynasd_client.rs:26-30`); a timeout becomes a transport error
and is reported as `503 backend_unavailable`/`storage_unavailable` instead of `504 timeout`
(`rynasd_client.rs:93-96,148-150`). The UI's `fetch` has no timeout or abort (`crates/rynas-ui/src/api.rs:66-110`).
Rule A25. Fix: one table of per-route deadlines in `rynasd_client`, `504 timeout` on expiry,
`AbortController` with a 30 s default in `api::send`. Owners: web, UI.

**M9 — pages swallow fetch errors and show skeletons forever.** `crates/rynas-ui/src/live.rs:173,176,216,227`
use `if let Ok(...)`; the storage, hardware and system pages render `Skeleton` while the signal is
`None` (`pages/storage.rs:36`, `pages/hardware.rs:23`, `pages/system.rs:80`), so a 503 looks like
"loading" indefinitely. Rule G2. Fix: keep `Result`/`Option<ApiErr>` next to each resource and add an
`ErrorState` component (code → `err.<code>` text, Retry). Owner: UI.

**M10 — the security page bypasses the component system with hand-built HTML.**
`crates/rynas-ui/src/pages/security.rs:93-115,310,366,422-425,433,438` build markup strings with a
local `esc()` and `inner_html`, including a hand-written status pill duplicating `Status`
(`ui.rs:41`). It saves wasm, but it forks the look of pills/banners, skips reactivity and makes escaping
a per-call-site concern. Rule G1. Fix: shared non-generic helpers (`fn kv_row(&'static str, String) -> AnyView`,
`Status` with `Signal` props) give most of the size win; keep `inner_html` for icons only. Owner: UI
(coordinate with the login-UI work in progress).

**M11 — two permanent SSE connections per tab on HTTP/1.1.** `/metrics/stream` and `/tasks/stream`
(plus notifications later) each hold one of the browser's 6 connections per origin; two tabs leave two
connections for all fetches, and the 30 s storage poll then stalls behind them. Rule A22. Fix: one
`/api/v1/events` stream per tab multiplexing named events (`metrics.sample`, `task.started`…) — or
HTTP/2 once HTTPS lands, but the server is `http1` only today (`Cargo.toml` axum features). Owners: web, UI.

**M12 — the wasm shell is over budget.** 354.7 KiB brotli vs 350 KiB (measurements above); without
the demo data 349.9 KiB, i.e. no headroom for the users/shares/tasks pages. Rule §3.1. Fix: C2
(demo off), then lazy-load the TOTP enrolment (QR code generator, `qrcodegen`) and the command palette,
check `serde_json` monomorphisation (one `Deserialize` path per API type: deserialize `MetricsSample`
with a hand-written visitor or `serde_json::from_str` behind one non-generic function), and report the
size in every UI PR. Owner: UI.

**M13 — no memory or task limits in the systemd units.** `packaging/systemd/rynas-web.service` and
`rynasd.service` have no `MemoryHigh`/`MemoryMax`/`TasksMax`; on a 4 GB box a leak in either (C1
shows how easy it is) competes with Samba and the page cache. Rule M7. Fix: values from guidelines §4.1,
plus `GLIBC_TUNABLES` (C1) in both units. Owner: packaging.

**M14 — the metrics ring stores ~20 heap allocations per sample.** `crates/rynas-web/src/metrics/mod.rs:26-63`
keeps 3 600 `MetricsSample`s, each with `Vec`s of `NetRate`/`DiskRate`/`Temperature` holding their own
`String` names (`lib.rs:57-83`): roughly 1–1.5 KB and ~20 allocations per sample, i.e. **4–5 MB of the
20 MB budget after one hour**, plus allocator fragmentation. Rules M4, §4.1. Fix: store a compact
struct-of-arrays per series (`f32`/`u32` values, names interned once in a series table, rebuilt only
when the device set changes); serialize to `MetricsSample` at the edge. Measure again after 1 h (not
done in this review: the ring needs an hour to fill). Owner: web.

### Minor

- **m1** `GET /api/v2/x` without a session answers `404 not_found`, `/api/v1/x` answers `401`
  (`crates/rynas-web/src/app.rs:38-39`): the 401-hides-existence rule should cover `/api/**`. Rule A23. Owner: web.
- **m2** List limits differ: revisions default 200, tasks 100, both max 1000 (`ops.rs:218,332`); no
  cursor. Rule A17: one default (50) and max (500) for every history list, `?before=`. Owner: rynasd.
- **m3** Lagged SSE subscribers silently skip events (`api.rs:134`, `ops.rs:402`); the task stream
  serializes each event once per subscriber (`ops.rs:398`) while metrics serialize once. Rule A21: send
  `resync`, serialize once into `Arc<str>`. Owner: rynasd, web.
- **m4** `index.html` is read from disk and its CSP hashed on every request
  (`crates/rynas-web/src/static_files.rs:84-93`): compute once at start (or on mtime change). Owner: web.
- **m5** Dynamic compression of large bodies: tower-http's default brotli on a missing `.br` cost
  27 ms and +7 MB retained RSS for the wasm (`app.rs:42`); `trunk build` output (dev, tests) has no
  `.br`. Configure `CompressionLayer` with gzip only or brotli quality ≤ 4, and a size floor; keep
  precompression in `packaging/build-deb.sh`. Rule S5. Owner: web.
- **m6** Fonts are served `Cache-Control: no-cache` (not hashed): one revalidation round-trip per font
  per load. Hash them via trunk or give `max-age=86400`. Rule S5. Owner: UI/web.
- **m7** `EventSource` closures are `forget()`-ed on every (re)connect (`crates/rynas-ui/src/live.rs:246,250,265`):
  three leaked closures per reconnect. Store them with the `EventSource` in `STREAM`. Rule M8. Owner: UI.
- **m8** Hard-coded colours in the chassis/bay drawing (`crates/rynas-ui/style/main.css:184,517-553,609`)
  although `--chassis`/`--chassis-2` tokens exist; the bay text colours are dark-theme values also in light
  theme. Rule G3. Owner: UI.
- **m9** Off-scale type and spacing: font sizes 10/11/26 px and many 2/3/5/6/7/10 px gaps/paddings in
  `main.css`; no spacing tokens. Rule G4. Owner: UI.
- **m10** Card markup differs per page: `card section` (storage) vs `card widget w-N` (others), skeleton
  inside a card on storage/hardware but bare on system/dashboard. Rule G2/§2.1 (`Card` component). Owner: UI.
- **m11** Date formatting duplicated (`pages/security.rs:60-67`, `notify.rs:103`) instead of a shared
  `i18n::datetime`; `t("st.members").to_lowercase()` (`pages/dashboard.rs:865`) transforms translated
  text. Rules G8, G9. Owner: UI.
- **m12** Same volume shown in SI (array size, `bytes_si`, `pages/dashboard.rs:865`) and IEC
  (filesystem size, `bytes`, `:841`) side by side. Rule G9 defines which is which; label units. Owner: UI.
- **m13** The dictionary allows English-only entries (21 keys such as `nav.storage`, `s.ok` have no
  Italian text): fine today, but the "Italian complete" check cannot tell a forgotten translation from an
  intentional one. Rule G8: always write both. Owner: UI.
- **m14** Charts animate a 450 ms slide on every 1 s sample (`crates/rynas-ui/src/chart.rs:221-240`):
  ~27 redraws/s per chart, 45 % of the time, and `collect()` allocates every series on every tick.
  Rule S2: ≤ 200 ms, reuse buffers, skip when the page is hidden. Owner: UI.
- **m15** `PendingBar` and `TaskPanel` (`crates/rynas-ui/src/shell.rs:361-403`) are static placeholders
  while `/config/pending` and `/tasks/stream` exist: wire them before more config pages land so every
  page shares them (A19/A20). Owner: UI.
- **m16** `rynas-web/Cargo.toml` pins its own `axum`, `tokio`, `clap`, `tracing` versions instead of
  `workspace = true` (rynasd uses the workspace ones): drift risk and duplicate builds. Owner: web.
- **m17** `docs/phase1/plan.md` "Steps" table lists steps 1–7 twice with contradictory statuses.
  Owner: coordinator.
- **m18** `rynasd` has no `thread_stack_size` and no arena limit (`main.rs:340-343`) while rynas-web
  documents both; align (rule M6). Owner: rynasd.

Naming is already consistent (plural nouns, verbs as POST sub-resources, `/v1` mirrors in rynasd). The
gaps are error codes (M2, M3), units (M6), duplicate models (M5) and the transport (M1, M8).

## What is good (keep it)

Single-thread runtimes and a dedicated collector thread; metrics pre-serialized once per sample into
`Arc<str>`; bounded rate-limit tables (10 000, LRU-ish eviction) and session limits; task history and
log caps; drivetemp reads gated on recent I/O; `smartctl -n standby`; precompressed `.br/.gz` in the
`.deb`; immutable caching of hashed assets; CSP with script hashes; canvas charts; UI history ring
capped at 600; i18n through one non-generic `tr()` to save wasm; reduced-motion support; visible focus.

## Suggested order

1. C1 (one-line `mallopt`s + unit tunables) and M13 — today, both daemons.
2. C2 (demo off by default), C3 (network statvfs), M9 (error states).
3. M2 + M3 + M8 together (error registry, rejections, timeouts), then M1 (one forwarder).
4. M6 + M5 before the users/shares API lands, so new endpoints start from the right types.
5. M4, M7, M11, M12, M14, then the minors.
